# 本地知识库质量与多模态能力设计

## 目标

把现有本地知识库助手从“能检索并回答”提升为“回答可核对、资料可管理、图片与 PDF 可理解、质量可持续评估”的本机应用。所有会话、索引、资料元数据、评测数据和反馈均保存在本机；DeepSeek 仅接收当前 Agent SDK 轮次所必需的用户问题、会话上下文和本地工具返回结果。

## 范围与分期

### 第一阶段：可信回答

- 每个回答来源展示文件名、页码、片段编号、检索得分和原文摘录。
- 来源可点击打开对应 PDF 页预览、图片预览或下载文件。
- 增加检索诊断：原始问题、实际检索词、候选片段数、命中片段及分数、最低得分阈值和无结果原因。
- 诊断只展示当前用户问题和本地检索结果，不展示 Agent SDK 的隐藏推理。
- 移除前端按“密码、token、key”等模式替换会话或工具内容的显示逻辑。内容由用户决定是否保存和显示。

### 第二阶段：资料生命周期与多模态

- 资料记录增加标签、说明、内容哈希、版本组和版本号；这些字段只保存在本机资产登记簿。
- 支持重命名显示名称、编辑标签和说明、替换为新版本、重新处理、删除、按标签筛选和重复内容提示。
- 替换版本创建新资产而不覆盖历史文件；同一版本组仅最新资产默认参与检索，历史版本仍可下载或恢复为当前版本。
- 文本和可提取文字的 PDF 继续走当前本地切片；图片与扫描 PDF 页生成本地预览，保存可选 OCR 文本和视觉描述。
- 多模态处理使用可选的本机 OCR/视觉适配器。适配器未配置或处理失败时，资料仍可作为附件和页图返回，界面明确显示“视觉文字尚未提取”，不会虚构图像内容。
- 问答检索把 OCR/视觉文本视为普通可引用片段，并保留图片或 PDF 页来源；回答来源卡片打开对应预览。

### 第三阶段：质量闭环

- 每个项目可维护本地评测问题集：问题、期望来源、可选期望答案、标签和启用状态。
- 批量评测只调用现有本地检索和 Agent SDK；结果记录检索命中、引用覆盖、回答文本、耗时、时间和错误，不把历史评测写入知识库。
- 每条助手回答可标记“有用”或“没用”，并可填写简短原因；反馈与会话消息关联，保存在本机。
- “没用”反馈提供“查看本轮检索诊断”和“基于原问题重新检索”入口；重新检索不会自动改写资料或参数。

## 架构与数据边界

1. `KnowledgeBase.search_with_diagnostics()` 作为检索唯一入口，返回 `results` 与 `diagnostic`。现有 `search()` 保留并委托给它，以避免破坏调用方。
2. `AssetStore` 扩展 `Asset` 元数据，但本地文件路径继续不暴露给模型或前端。资产 API 返回展示名、标签、版本、处理状态和预览 URL。
3. `AssetProcessor` 扩展为可重复处理的管道：预览、文本/PDF 提取、可选视觉文字提取、索引重建。处理失败只标记本资产失败，不影响已就绪资产。
4. Agent SDK 的 `search_knowledge` 工具同时返回来源片段和诊断摘要；服务端把诊断保存到该条助手消息的 `agent.retrieval` 字段。模型只依据来源片段回答，前端独立渲染诊断。
5. 评测与反馈各使用单独的本机 JSON 存储，不混入会话记录、知识库文件或 SDK session JSONL。

## 前端交互

- 回答下方的“来源”默认显示紧凑卡片；展开后显示摘录、分数和“打开原文”。
- “检索诊断”默认折叠，显示命中数量或无结果原因；展开后显示实际查询、阈值和候选片段。
- 知识库页面保留现有上传和处理参数区，在其下增加资料列表、筛选、资料详情抽屉和版本历史。
- 资料替换、删除和恢复版本是明确的按钮操作；替换/恢复前展示将影响的检索范围，删除沿用现有确认对话框。
- 项目页新增“评测”入口；会话中新增对单条助手消息的反馈按钮。

## 错误与降级

- 检索为空时，诊断返回 `no_query_terms`、`no_ready_documents`、`below_minimum_score` 或 `no_matching_chunks` 之一；回答仍遵守“资料不足”的现有规则。
- 无预览、页码非法或资产已删除时，来源卡片显示不可用状态而不是失效链接。
- OCR/视觉适配器不可用、超时或返回无文字时，资产状态保持可用；只将视觉提取状态标为 `unavailable`、`failed` 或 `empty`。
- 评测单题失败不会中断其他题；每题保存可行动错误信息。

## 验收标准

1. 一个文本或 PDF 问题的回答可查看命中来源、页码、片段、得分和摘录；其页面链接可打开正确预览。
2. 无命中问题能在诊断中看到明确原因，普通回答不会伪造来源。
3. 当前用户输入的任意文本在对话与工具轨迹中按原样显示；明确写入仍只由当前用户指令授权。
4. 资料可添加标签、重命名、重新处理、替换为新版本和删除；项目检索只使用当前版本。
5. 图片和扫描 PDF 在视觉适配器已配置时可被检索并以可点击图片/PDF 页引用；未配置时有明确降级提示。
6. 评测集可运行并保留项目内结果；回答反馈可保存、加载并触发重新检索。
7. 每阶段都有后端单元测试、前端交互/契约测试、类型检查和构建验证；结束后由用户人工检查真实页面。
