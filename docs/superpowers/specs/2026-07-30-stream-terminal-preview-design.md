# 流式终止恢复与资料弹窗预览设计

## 目标

在本地修复两项体验问题：流式 SSE 偶发提前断开时不把已经或即将落库的回答误报为失败；点击知识库来源文件的在线预览时，在当前页面弹窗展示文件内容，而非打开新标签页。

## 已确认事实

- 本地 FastAPI、真实 Chromium 和 DeepSeek 调用均能接收 `status → trace → delta → done`，且服务端在 `done` 前已写入完整会话。
- 页面提示“流式回答未正常结束。”只来自前端的 EOF 兜底分支。
- 当前兜底只读取一次会话；若网络或代理先关闭浏览器侧流、而后端仍处于最终写入窗口，就会产生错误提示。
- 当前来源文件的眼睛图标是带 `target="_blank"` 的链接。

## 方案

### 流式传输

1. `SdkAgentRunner.stream()` 在等待 Node Agent SDK 子进程输出时，每 15 秒产生一个 `heartbeat` 公共事件。
2. `KnowledgeAgent.answer_stream()` 原样转发该事件；SSE 响应因此持续有字节输出，避免中间代理把静默连接误判为失活。
3. 前端在流自然 EOF 且没有收到 `done` 时，不重试模型请求。它改为每秒读取同一会话，最多等待 95 秒；一旦会话在本轮起点后新增完整的用户消息和非空助手消息，即加载该已保存答案并视为成功。
4. 服务端明确发出的 `error` 事件仍立即显示原始错误，不进入轮询恢复。轮询到期且没有完整回答时，保留“流式回答未正常结束。”作为真实失败提示。

这样既避免重复模型调用和重复写入，也能覆盖“浏览器流先断、服务端随后完成落库”的时序。

### 文件预览

1. App 根组件维护当前要预览的资料，并使用 HeroUI `Modal` 在页面内显示。
2. 所有来源文件的在线预览按钮改为普通按钮，阻止外部导航并打开该弹窗；对话中已上传附件也使用同一入口。
3. 弹窗使用现有 `/api/assets/{id}/view`：图片用 `img`，PDF 和浏览器可渲染的文本资料用受限 `iframe`。下载仍是独立下载动作。
4. 不改变资产存储、S3、MySQL、检索或下载接口。

## 错误处理与边界

- 恢复期显示“流连接中断，正在同步已保存的回答…”，让用户知道页面没有重新提问。
- 取消生成继续走 `AbortController` 分支，不做恢复轮询。
- 预览仅使用既有同源资产接口；没有预览权限或文件未就绪时由现有接口返回错误，不自动下载。
- 本次只在本地实现、构建和测试；不部署、不推送、不改服务器。

## 验收

- 后端能转发心跳事件，正常的 `done` 语义不变。
- 前端有可测试的轮询恢复函数，且显式 SSE `error` 不触发它。
- 预览图标与已上传附件不再有 `target="_blank"`，而是打开命名清晰的站内弹窗。
- 前端静态回归、TypeScript/Vite 构建和相关 Python 测试通过。
