# 启动重建坏资产隔离设计

## 目标

当应用启动时发现索引与资产登记状态不一致，需要重建索引；若某个已标记为 `ready` 的资产源文件已经缺失或无法解析，只让该资产进入安全失败状态，不再让它阻断 FastAPI 和 Tauri 桌面端启动。

修复必须保留其余可读取资产的检索结果，不删除原始资产登记，也不自动创建、覆盖或删除 S3 对象。失败资产仍可通过现有“重新处理/扫描”流程重试。

## 当前故障

`startup()` 在加载资产和索引后调用 `index_state_requires_rebuild()`。一旦需要重建，`rebuild_ready_assets()` 会把所有当前版本的 `ready` 资产交给 `KnowledgeBase.rebuild()`。

`KnowledgeBase.rebuild()` 在逐个读取资产时没有保留失败资产的身份。任一 `path_for(asset)` 或解析步骤抛出异常，整次重建立即终止，异常继续传播到 FastAPI lifespan，最终导致服务和桌面端都无法启动。

当前现场中的失败资产已登记为 `ready`，但它对应的 S3 对象不存在，因此 `AssetStore.path_for()` 抛出 `FileNotFoundError`。

## 方案

### 带资产身份的重建错误

在知识库层定义一个内部异常，携带失败的 `asset_id`，但不把存储路径、S3 键、解析器细节或原始异常消息暴露给公共 API。

`KnowledgeBase.rebuild()` 继续先在内存中构造完整候选索引；对每个资产的路径读取和片段生成建立资产级错误边界。某个资产失败时，抛出带该资产 ID 的异常，且不发布半成品索引。

### 失败资产隔离与重试

`rebuild_ready_assets()` 保持现有重建锁，并按以下顺序恢复：

1. 读取当前版本的 `ready` 资产并尝试全量重建。
2. 若收到带资产身份的重建错误，从现有索引中移除该资产的旧片段。
3. 使用现有 `AssetStore.publish_failed()` 原子更新资产状态、错误文案和所有资产的片段数量。
4. 重新读取剩余 `ready` 资产并重试全量重建。
5. 重建成功后按现有逻辑同步最终片段数量并返回统计。

每轮至少会移除一个失败资产，因此重试次数受本轮初始 `ready` 资产数量限制，不会无限循环。与资产无关的异常继续向上传播，避免把配置错误或程序错误误判为文件损坏。

失败资产使用现有安全文案“文件解析或预览生成失败”，不泄露私有存储位置或底层异常。

## 并发与一致性

- 整个恢复循环仍位于 `knowledge_base.rebuild_transaction()` 中，与上传发布、删除、替换和手动重建串行化。
- `KnowledgeBase.rebuild()` 只有在所有候选资产成功解析后才替换持久化索引，失败时保留之前的完整索引。
- 标记失败前先移除该资产旧片段，再通过 `publish_failed()` 同步登记状态和所有片段计数，保持 `ready` 与索引成员关系一致。
- 不修改 S3、MySQL 连接配置、文件内容或桌面端生产地址。

## Tauri 本地启动

修复通过后，后端使用 `127.0.0.1:8000` 启动。Tauri 开发命令使用临时 `--config` 覆盖：

- `build.devUrl` 指向 `http://127.0.0.1:8000`；
- 主窗口 URL 指向相同地址；
- 不修改仓库中默认加载远程站点的 `tauri.conf.json`。

FastAPI 从现有 `frontend/dist` 提供页面和同源 API；Tauri 仅创建原生窗口并使用系统 WebView 渲染该本地页面。

## 测试与验收

新增回归测试构造两个已经成功索引的资产，然后删除其中一个源文件并制造索引计数漂移：

- 修复前：`startup()` 抛出 `FileNotFoundError`，测试失败。
- 修复后：`startup()` 正常返回；缺失资产为 `failed` 且片段数为 0；可读资产仍为 `ready`，片段与登记数量一致且仍可检索；失败文案不包含私有路径。

随后运行完整 Python、前端和 Agent SDK 检查，并进行实际启动验证：

- `GET /api/status` 返回 HTTP 200；
- Tauri 开发进程持续运行且创建 Knowledge Helper 桌面窗口；
- 桌面窗口加载本地 `127.0.0.1:8000`，不是生产远程地址；
- 工作树只包含预期的设计、测试和实现变更。

## 不在范围内

- 不自动删除缺失资产的登记记录。
- 不自动恢复或重新上传缺失的 S3 对象。
- 不改变 S3 下载层对“对象不存在”和“临时连接失败”的现有归一化行为。
- 不修改 Tauri 生产打包目标、签名、CSP 或远程默认地址。
