# 紧凑来源预览与下载设计

## 目标

回答中的来源文件默认保持紧凑；用户点击文件名时，才在其下方展开该文件命中的来源摘录卡片。每个文件提供在线预览和下载两个独立图标操作。

## 界面与行为

- 保留回答下方的来源文件区域；每个来源按文件名去重，避免同一文件的多个片段重复出现。
- 每个来源文件默认收起。点击文件名可独立展开或收起该文件的命中摘录；展开内容仅包含该文件的片段标题、页码（如有）和摘录，不显示检索得分。
- 每个文件显示两个带中文悬停说明的图标：
  - 预览：在新标签页打开本地的内联预览地址。图片、PDF 及浏览器可直接显示的文本使用原文件内容；不支持的格式返回明确的“无法在线预览”提示，绝不退化成下载。
  - 下载：触发浏览器下载原始文件，使用 `download_url` 与 `download` 属性。
- 引用对象保留已有的 `excerpt`、`page` 等字段；前端只在用户展开来源时使用，后端检索、附件与“检索诊断”不变。
- 新增预览端点，与下载端点分离；预览响应使用 `Content-Disposition: inline`，下载响应继续使用附件下载语义。

## 验收

- 一条回答命中多个片段时，来源区每份文件仅显示一次。
- 文件名可单独展开/收起它自己的摘录卡片；多个文件可同时展开。
- 来源摘录默认不显示，且不显示片段得分或“打开原文”。
- 预览图标不会触发下载；下载图标始终使用下载 URL。
- 前端类型检查、lint、构建、来源 UI 合约测试，以及后端预览端点测试通过。
