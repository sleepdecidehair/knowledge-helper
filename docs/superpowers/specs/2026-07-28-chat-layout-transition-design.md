# 新对话切换与固定会话视图设计

## 目标

新建对话时保留欢迎页的简洁引导；用户提交首个问题后立即进入正式会话视图。正式视图的外层高度与宽度保持稳定，后续消息和流式内容只在其内部滚动。

## 已确认的交互

- 欢迎页显示“今天想了解什么？”和其下方的输入框。
- 用户提交首个问题后，立刻切换为正式对话视图；不在欢迎页等待流式回答。
- 正式对话视图使用当前流式页面的最大可用区域作为固定外框；不会随着消息数量、回答长度或流式生成改变尺寸。
- 会话内容在外框内部滚动，输入框固定在该视图的底部。

## 方案比较

1. 推荐：在已有 `conversation` 状态首次写入本轮用户消息和空助手消息时立即渲染正式视图；以 CSS Grid 将会话区域分为可滚动内容区与底部输入区。最小化状态改动，并天然适配流式更新。
2. 增加独立路由或单独视图状态。能更明确地区分欢迎页和对话页，但当前应用没有路由需求，会额外增加状态同步与历史会话恢复复杂度。
3. 保持现有页面结构，仅把输入框定位到底部。无法解决首问仍停留在欢迎页，也不能约束内容区高度，因此不采用。

## 实现边界

- 复用既有 `conversation`、`hasMessages`、`sendQuestion()` 和 SSE 流程；不改后端 API、会话数据和模型调用。
- `sendQuestion()` 创建会话后，立刻设置含用户消息和占位助手消息的会话状态，再进行附件处理和流式请求。
- CSS 为聊天工作区定义基于视窗的稳定高度；消息容器使用 `overflow-y: auto`，输入区放在工作区内而非页面固定定位。
- 小屏幕仍允许合理收缩，但保持“外框固定、内容内部滚动”的原则。

## 验收与测试

- 静态前端测试验证欢迎页输入区、首次提交后的即时会话状态，以及固定高度/内部滚动的 CSS 约束。
- 手动验证：点击新建对话后输入问题，页面立即出现用户问题和流式助手占位；滚动长回答时外框与输入区不移动。
- 不部署、不推送；仅在本地构建可用后合并至本地 `dev`。

## 自检

- 范围仅覆盖聊天布局与首问切换，没有改变模型、历史记录或知识库逻辑。
- “固定”明确为外层布局稳定，而非禁止内容滚动；移动端保留可用的响应式尺寸。
